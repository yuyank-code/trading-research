# Research Run — 2026-09-18

## Meaningful progress

This run adds a new hardening hypothesis: **H59 — execution-price causality and latency sentinel**.

### Motivation

Leakage is not limited to feature preprocessing. A backtest can also become non-causal when a signal computed from bar `t` is executed at a price that was only known after the signal timestamp, or when spread/slippage is applied using future market conditions. For FX, this is especially important because bid/ask quotes, bar closes, and execution timestamps are not interchangeable.

### H59 hypothesis

A causality-audited execution engine should produce materially different results from an intentionally non-causal engine on adversarial data where the next-bar price/spread is made predictive of execution. The audit should flag every use of information with availability time after the order decision time.

### Required test

1. Define separate `event_time`, `decision_time`, `order_time`, and `fill_time`.
2. Construct signals using only fields available by `decision_time`.
3. Execute no earlier than `fill_time`, with explicit latency.
4. Use contemporaneous bid/ask or a conservative spread model; never future spread/volatility to price a fill.
5. Inject future-dependent spread and next-bar-price fields into an adversarial fixture.
6. Require the causality sentinel to fail the fixture while the clean fixture passes.
7. Re-run net OOS evaluation with fixed costs and stressed costs (+25%, +50%, +100%).
