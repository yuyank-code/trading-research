# Research Run — 2026-09-11 08:17

## Meaningful pipeline finding
The production research engine uses a 6-bar forward-return label and purges six bars at each walk-forward boundary. The execution simulator, however, enters on the next bar and resolves the trade from that next bar's OHLC. This is not direct label leakage, but it creates a prediction/execution horizon mismatch. The research standard should therefore compare labels and executable events with explicitly aligned horizons before promoting profitability.

## New literature evidence
- Kim (2026), *Beyond Accuracy: A Validation Framework for Machine Learning in Cryptocurrency Trading*, reports 340 crypto strategy variants and finds that AUC-only validation produced substantial false positives; their Monte Carlo study reports false positives falling from 27% with AUC-only validation to 0% with CPCV + PBO. They also report transaction costs consuming 55–91% of gross alpha. This strengthens the requirement for multiplicity-aware OOS validation and explicit costs.
- Bysik & Ślepaczuk (2026), *Machine Learning-Based Bitcoin Trading Under Transaction Costs*, evaluates ~70,000 hourly BTC observations using 27 walk-forward folds. Naive sign strategies fail under 10 bps costs, while forecast-magnitude cost filters improve selected configurations; formal bootstrap evidence does not establish model dominance.
- Huang, Wang & Jiang (2026), *Research on Machine Learning High-Frequency Trading Strategy of Cryptocurrency Based on Transaction Cost-Aware Filtering*, similarly reports a large prediction-to-trading gap and emphasizes cost-aware filtering over architectural complexity.
- Zhai (2026), *The Prediction Paradox*, reports a live ETHUSDC study where high walk-forward AUC did not translate into live economic value, reinforcing the need to test execution/prediction alignment and regime stability.

## Pipeline change
The main repo's `validation.py` previously detected duplicate prediction timestamps but then deduplicated the data and continued computing metrics. That could silently hide a generator defect and alter the evaluated sample. It now **fails closed**: duplicate timestamps set `validated=False` and return before any classification/equity metrics are calculated.
